# Contributing to StickerBridge

Thanks for helping! The most valuable contribution right now is **experiment results from different devices**.

## Workflow
1. Fork the repo and create a branch:
   - `experiment/<id>-<name>` for experiments (e.g. `experiment/e1-ime-probe`)
   - `feature/<name>` for product features
   - `fix/<name>` for bug fixes
   - `docs/<name>` for documentation
2. Keep pull requests small and focused. Fill in the PR template.
3. Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `chore:`, `test:`, `experiment:`.

## Never commit personal data
Before every commit, check `git status` and make sure none of these are included:
- Real WhatsApp stickers or sticker packs (even your own)
- Screenshots of real chats or profiles
- Device logs, `adb` dumps, bug reports
- Linked-device session files, databases, backups (`*.db`, `*.crypt*`)
- Keystores, `local.properties`, `.env`, Facebook App IDs or any keys

Test images must be **synthetic** and generated by a script in the repo.

## Reporting experiment results
Use the "Experiment result" issue template. Include: device model, Android/iOS version, Instagram version, WhatsApp version, and the results table from the experiment doc. Describe what you saw in words instead of attaching private screenshots.

## Code style
- Kotlin: official Kotlin style, 4 spaces.
- Keep dependencies minimal; open an issue before adding a new one.
- No analytics, no network calls unless a feature explicitly needs them.

## Code of conduct
Be respectful and constructive. Harassment of any kind is not tolerated.
