# E1 — IME probe

Throw-away experiment for [docs/experiments/E1-ime-probe.md](../../docs/experiments/E1-ime-probe.md).

**Question:** which rich-content MIME types do Instagram input fields (DM composer, story text tool, comment field) accept from a keyboard?

The app installs a keyboard called **IME Probe**. When a text field gets focus it shows and logs the field's `packageName`, `fieldId`, `inputType`, `imeOptions`, `hintText` and `EditorInfoCompat.getContentMimeTypes()`. Four buttons (PNG, WEBP, Animated WEBP, GIF) try to insert a bundled synthetic image with `InputConnectionCompat.commitContent` (FileProvider URI + `INPUT_CONTENT_GRANT_READ_URI_PERMISSION`). The result (`true` / `false`) and whether the MIME type was advertised by the field are shown and logged. Buttons are never hidden, even for non-advertised types.

The launcher app **E1 IME Probe** shows the log and has *Open keyboard settings*, *Share log* and *Clear log*.

## Privacy

- No permissions at all: no internet, storage, accessibility or contacts.
- The keyboard has no letter keys and never reads or logs typed text (no `getTextBeforeCursor`, no `getExtractedText`, no `initialSurroundingText`).
- The log lives in app-internal storage (`filesDir/ime_probe_log.txt`) and only leaves the phone if you press *Share log*.
- Test images are synthetic (`res/raw/`), generated by `tools/generate_assets.py`.
- **Before pasting a shared log into an issue or doc**, check it: `hintText` and `packageName` of other apps you focused are in it.

## Requirements

- Android Studio (Ladybug or newer) with Android SDK Platform 35, **or** JDK 17 + Android SDK command-line tools
- An Android 8.0+ (API 26) phone with USB debugging enabled
- `adb` on `PATH` (it is in `%LOCALAPPDATA%\Android\Sdk\platform-tools`)

Versions: Gradle 8.11.1 (wrapper), AGP 8.7.3, Kotlin 2.0.21, compileSdk/targetSdk 35, minSdk 26. Dependencies: `androidx.core`, `androidx.appcompat`.

## Build

### Android Studio
1. *File → Open…* → select `experiments/e1-ime-probe` (this folder, not the repo root).
2. Wait for Gradle sync. Android Studio creates `local.properties` with your SDK path (ignored by git).
3. *Build → Build App Bundle(s) / APK(s) → Build APK(s)*, or press *Run* with the phone connected.

### PowerShell
```powershell
cd experiments\e1-ime-probe
# only needed if Android Studio has not created local.properties yet:
"sdk.dir=$($env:LOCALAPPDATA.Replace('\','/'))/Android/Sdk" | Out-File -Encoding ascii local.properties
.\gradlew.bat assembleDebug
```
APK: `app\build\outputs\apk\debug\app-debug.apk`

Gradle needs JDK 17+. If `java -version` shows something older, point `JAVA_HOME` to Android Studio's JBR:
```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

## Install

```powershell
adb devices
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Enable the keyboard

1. Open **E1 IME Probe** → *Open keyboard settings* (or *Settings → System → Languages & input → On-screen keyboard → Manage keyboards*).
2. Turn on **IME Probe**. Android warns that a keyboard "may be able to collect all the text you type" — this is the standard warning for every keyboard; this one has no keys and reads no text.
3. In any text field, switch keyboards with the keyboard icon in the navigation bar or the system picker. On the probe, *Next keyboard* switches back to your normal keyboard.

Optional (adb):
```powershell
adb shell ime enable dev.stickerbridge.e1.imeprobe/.ProbeImeService
adb shell ime set dev.stickerbridge.e1.imeprobe/.ProbeImeService
# back to your normal keyboard afterwards:
adb shell ime reset
```

Live log while testing:
```powershell
adb logcat -s ImeProbe
```

## Test checklist

From [docs/experiments/E1-ime-probe.md](../../docs/experiments/E1-ime-probe.md):

Setup
- [ ] Android phone (Android 8+), Instagram installed and logged in
- [ ] A second account or a friend to receive test messages
- [ ] This debug APK installed

Steps
1. [ ] Enable "IME Probe" in system keyboard settings.
2. [ ] For each field, focus it, switch to IME Probe, and write down the info shown:
   - [ ] DM composer
   - [ ] Story text tool
   - [ ] Comment field
3. [ ] In each field press PNG, WEBP, Animated WEBP and GIF. Note whether `commitContent` returned true or false and what happened.
4. [ ] Check what the recipient sees on Android, iOS and Web.

Success / failure
- **Success:** the DM field lists at least one image type, and a sticker arrives.
- **Failure:** `null`/empty list, or `commitContent` returns false → share-intent fallback.

Record the results (text only, no screenshots of real chats) in the *Results* table of `docs/experiments/E1-ime-probe.md`, including device, Android version, Instagram version and date.

## Regenerating the test images

```powershell
cd experiments\e1-ime-probe
python -m pip install Pillow
python tools\generate_assets.py
```
The script overwrites the four files in `app/src/main/res/raw/` and fails if any is ≥ 200 KB or if an animated file has fewer than 3 frames. Each image is a 512×512 transparent canvas with a coloured shape, "TEST" and a frame label.

| File | MIME | Frames |
|---|---|---|
| `test_png.png` | image/png | 1 |
| `test_webp.webp` | image/webp | 1 |
| `test_webp_animated.webp` | image/webp | 4 |
| `test_gif.gif` | image/gif | 4 |
